# 画像アンケート（第1段階）＋ Pong

探究の第1段階で使うWebアプリです。画像を2枚ずつ見せて、よいと思うほうを選んでもらい、いいね数（調査用に設定した数字）が選択を動かすかを調べます。回答を終えた人はPongで遊べます。

- フレームワーク：Next.js 15（App Router）＋ TypeScript
- データ保存：Upstash Redis（Vercel の Marketplace から追加）
- オンライン対戦：Ably
- 画像の組と数字：`content/pairs.ts`
- フォーム作成：`gas/create_form_stage1.gs`

## 実験のしくみ

出題画面はSNSの投稿風です。「どちらの投稿に『いいね』しますか？」と聞き、画像かハートを押すと「いいね」が付いて次へ進みます。
いいね数はハートの横に大きく表示し、押すと1増えます。数字なし群では、同じ場所に「いいね」とだけ表示します。
（数字を目立たせているのは、操作する変数が気づかれないまま終わらないようにするため。どちらを選ぶかは誘導していません。論文の方法の節に書いてください）

| 条件 | 見えるもの |
|---|---|
| 数字なし | 画像2枚だけ |
| 数字あり(X) | 画像2枚＋いいね数 |
| 数字あり(Y) | Xと同じ。ただし多い数字が付く画像が逆 |

- 開始した人は、**人数が一番少ない条件**に入ります（同数なら無作為）。比は `content/pairs.ts` の `WEIGHTS` で変えられます。
- 12組（互角6・中くらい4・はっきり2）。出題順と左右は人ごとに無作為です。
- 数字あり群では、1人の中で「aに多い数字」が6回、「bに多い数字」が6回になります。
- 参加者はcookieのUUIDで見分けます。同じブラウザで開き直すと、続きから（終了済みなら完了コードだけ）になります。

**仮説（実施前に記録）**
1. 互角の組では、数字あり群の7割以上が、いいねの多いほうを選ぶ。
2. 好みがはっきりした組では、その影響が弱まる。

## 画像について

- **互角の6組（`e01`〜`e06`）**：模様を自動生成したもの（`tools/make_images.py`）。著作権の問題はありません。
- **中くらい・はっきりの6組**：Wikimedia Commons の写真です。**Vercelでビルドするときに自動でダウンロード**します（`scripts/fetch-photos.mjs`）。
  - 使う写真は `content/photos.json` に、Commons のファイル名で書いてあります。
  - ライセンス・作者名・出典URLもビルド時に Commons から取得し、出典ページ（`/credits`）に自動で表示します。出典ページへのリンクは、出題画面と終了画面の下にあります。
  - ダウンロードに失敗したらビルドが止まります（仮の画像のまま公開されないように）。一時的な問題なら Redeploy で直ります。
  - リポジトリに入っている `m01a.jpg` などは仮の画像で、ビルド時に上書きされます。

**デプロイしたら、必ず12枚を目で確認してください。** 写真はファイル名と説明だけで選んでおり、中身は見ていません。人の顔が写っている、明るさや出来が極端に違う、などがあれば `content/photos.json` のファイル名を別の写真に変えて Redeploy します。

写真を選ぶときの目安：
- 人が写っていないもの
- 2枚の明るさや写真のうまさに差が出すぎないもの（差があると、好みではなく写真の質で選ばれる）
- ライセンスが CC0・パブリックドメイン・CC BY・CC BY-SA のもの（Commons にある写真はどれかに当てはまります）

## デプロイ手順（Vercel）

1. このフォルダを GitHub の非公開リポジトリにアップロードする
2. Vercel で「Add New → Project」→ リポジトリを選んで Deploy
3. **Storage → Upstash for Redis** を追加してプロジェクトにつなぐ
4. **Settings → Environment Variables** に次を追加
   - `ADMIN_KEY`：12文字以上の、自分しか知らない文字列（データ取り出し用）
   - `ABLY_API_KEY`：AblyのAPIキー（Pongのオンライン対戦用）
5. **Deployments → Redeploy**
6. 表示されたURLを `gas/create_form_stage1.gs` の `APP_URL` に入れてフォームを作る

> AblyのAPIキーは環境変数にだけ置き、コードやGitHubには書かないでください。
> ブラウザにはキーそのものは渡らず、`pong:` で始まるチャンネルだけに使える1時間の許可が発行されます。

## データの取り出し

- 1回の選択が1行：`https://xxxx.vercel.app/api/export?key=管理キー&type=trials`
- 1人1行のまとめ：`https://xxxx.vercel.app/api/export?key=管理キー&type=summary`

**分析のしかた（trials のCSV）**
- 仮説1：条件が「数字あり」、種類が「互角」の行で、「多いほうを選んだ」の平均を出す。影響がなければ0.5。
- 仮説2：同じ平均を、種類ごと（互角／中くらい／はっきり）に比べる。
- 基準：条件が「数字なし」の行で、組ごとの「aを選んだ」の平均を出す。0.5に近い組ほど本当に互角。
- 「速すぎ」が1の行（0.4秒未満）は、適当に押した可能性がある。除いた場合の結果も確認する。
- 完了コードで、フォームの回答とつなげられる。

## Pong

- 回答を終えた人だけ遊べます（終了画面の一番下の小さな「暇？」ボタンから）。7点先取。
- 画面は、ウィンドウの幅と高さの両方に収まる一番大きいサイズになります（縦横比 8:5）。
- ゲームの中は 800×500 の座標で計算し、描くときだけ画面に合わせて拡大・縮小します。オンライン対戦で送る位置や速さもこの座標なので、相手と画面の大きさが違っても公平です。
- 文字はピクセルフォント DotGothic16（SIL Open Font License、`@fontsource/dotgothic16` でサーバーに同梱）。
- CPUと対戦（3段階）／2人で対戦（同じ端末）／オンライン対戦（おまかせ・部屋番号）
- オンライン対戦は、自分のパドルに当たったかどうかを自分の端末が判定する方式です。
- `ABLY_API_KEY` がないと、オンライン対戦だけ使えません（他は動きます）。
- `public/vendor/ably.min.js` は Ably 公式のブラウザ用ファイル（Apache-2.0）です。

## ローカルで動かす（任意）

```bash
npm install
npm run dev   # http://localhost:3000
```

ネットにつながらない環境では `SKIP_PHOTO_FETCH=1 npm run build` で写真のダウンロードを省略できます（仮の画像のまま）。

模様の画像を作り直すとき：`python3 tools/make_images.py`
